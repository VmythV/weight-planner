# 减重计划

设定"哪天减到多少公斤"，根据每天的称重生成个性化减重计划：平滑的计划曲线、每天可以摄入多少、需要消耗多少，并且每周按实际进度自动校准。

第 1 阶段（当前）：手动录入或批量导入体重。
第 2 阶段（已跑通）：ESP32 监听小米体脂秤 S400 Pro 的蓝牙广播，称完自动上报，见下文「ESP32 自动上报」。

后续待办见 [TODOLIST.md](TODOLIST.md)，系统架构见 [docs/architecture.html](docs/architecture.html)。

## 快速开始

```bash
brew install uv            # 已安装可跳过
uv sync
cp .env.example .env       # 填写登录密码和 API 令牌，见下文「访问控制」
uv run uvicorn app.main:create_app --factory --host 0.0.0.0 --port 8765
```

打开 http://localhost:8765 ，输入密码登录，先在「计划设置」里填写身高、年龄、目标体重和日期，再记录一次体重。

## 部署到 Mac mini

1. 把整个 `weight-planner` 目录拷到 Mac mini（例如 `~/weight-planner`）。
2. 运行 `deploy/install-launchd.sh`。它会安装依赖，并注册为登录后自动启动、崩溃后自动重启的后台服务。
3. 手机连同一个 Wi-Fi，打开脚本最后打印的地址（形如 `http://mac-mini.local:8765`）。可以"添加到主屏幕"当 App 用。

Mac mini 上还需要设置两处：

- **系统设置 → 能源**：打开"显示器关闭时防止自动进入睡眠"，否则睡眠时收不到数据。
- **自动登录**：LaunchAgent 在用户登录后才运行，停电重启后需要自动登录（系统设置 → 用户与群组）。

第一次有设备访问时，macOS 可能会询问是否允许 Python 接受传入连接，选"允许"。

数据保存在 `data/weight.db`（SQLite），备份这一个文件即可。可以用环境变量 `WP_DB` 改存放位置。

## 访问控制

配置写在项目根目录的 `.env`（已加入 `.gitignore`，模板见 `.env.example`），同名环境变量优先。改完重启服务生效。

| 配置项 | 说明 |
|---|---|
| `WP_PASSWORD` | 网页登录密码。不填时不做任何验证，只适合本机开发 |
| `WP_API_TOKENS` | 给 ESP32 和其他系统用的令牌，逗号分隔，格式 `名称:令牌`，例如 `esp32:3f9a…,homeassistant:81bc…` |
| `WP_SESSION_DAYS` | 网页登录有效天数，默认 30 |
| `WP_SECRET_KEY` | 可选，登录 Cookie 的签名密钥。不填时由密码派生，改密码后所有设备都要重新登录 |
| `WP_DB` | 数据库位置，默认 `data/weight.db` |

- **网页**：未登录时打开任何页面都会跳到 `/login`。同一 IP 15 分钟内输错 5 次密码，要等这段时间过了才能再试。退出登录在「计划设置」底部。
- **接口**：除登录接口和静态文件外，所有 `/api/*` 和接口文档 `/docs` 都需要登录 Cookie 或 API 令牌，否则返回 401。
- **生成令牌**：`python3 -c "import secrets; print(secrets.token_hex(24))"`，每个接入的系统用一个单独的令牌，不用时从 `WP_API_TOKENS` 里删掉就失效。

```bash
curl -H "Authorization: Bearer <令牌>" http://mac-mini.local:8765/api/weighins?limit=10
curl -H "X-API-Key: <令牌>" http://mac-mini.local:8765/api/session   # 返回令牌名称，用来确认配置
```

> 服务本身是 HTTP，密码和令牌在网络上是明文传输。家庭局域网内可以直接用；要暴露到公网，请在前面加一层 HTTPS（如 Caddy、Nginx 或 Cloudflare Tunnel）。

## 使用方式

### 1. 第一次使用：填写计划设置

点页面右上角的齿轮打开「计划设置」，填写后点"保存计划"：

| 字段 | 说明 |
|---|---|
| 性别、年龄、身高 | 用于计算基础代谢 |
| 日常活动水平 | 按平时每周运动几天选择；拿不准就选"轻度" |
| 目标体重、目标日期 | 想在哪天减到多少公斤 |
| 计划开始日期 | 默认今天。计划曲线从这一天开始画 |
| 每天额外运动消耗 | 计划每天通过运动额外消耗的热量，没有固定运动就填 0。填了之后可摄入量会等量增加。运动消耗容易被高估，建议保守填写 |
| 起始体重 | 可留空。留空时取开始日的趋势体重；开始日之前没有称重，则取第一次称重 |

如果在「每天额外运动消耗」里单独填了运动量，「日常活动水平」就按不运动时的状态选（久坐或轻度），避免重复计算。

保存后，表单下方会显示计划摘要：每天需要摄入多少、开始阶段每周减多少。页面顶部出现黄色或红色提示时，说明计划不够安全，按提示把目标日期延后，或增加运动量。

### 2. 每天记录体重

- 建议**每天早上起床、上完厕所、吃东西之前**称一次。时间越固定，趋势越准。
- 点右上角「记录体重」：左右拖动刻度尺，或按住 − / + 微调（每次 0.05 kg），默认值是上一次的体重。时间可选"现在 / 今天早上 / 昨天早上 / 其他时间"。
- 一天称了多次，只按**最早的一次**计算，其余的仍然保留在记录里。
- 记错了，在「称重记录」里点那一条，就能修改体重和时间，或者删除。默认显示最近 10 条，点"显示全部记录"能看到更早的。
- 补录历史数据：在「计划设置」底部展开「批量导入历史数据」，每行一条，支持以下格式（只有日期的按早上 8 点记）：

  ```
  2026-09-01,86.2
  2026-09-02 07:30,85.9
  ```

  表头之类无法识别的行会被跳过，并提示是第几行。

### 3. 看懂今日卡片

| 卡片 | 含义 |
|---|---|
| 今天可以摄入 | 今天的热量上限，以及建议的蛋白质、脂肪、碳水克数 |
| 今天预计消耗 | 按当前趋势体重估算的全天消耗，拆成基础代谢、日常活动、额外运动；额外运动会折算成快走步数 |
| 热量缺口 | 消耗减去摄入，以及按这个缺口每周大约能减多少公斤 |
| 趋势体重 | 去掉日常水分波动后的体重，以及与今日计划体重的比较 |
| 进度 | 已减多少、还差多少、剩余天数，以及按建议摄入预计哪天达到目标 |

趋势体重旁边的状态标签：

| 状态 | 条件 |
|---|---|
| 领先计划 | 趋势体重比计划低 0.5 kg 以上 |
| 按计划进行 | 趋势体重不高于计划 |
| 略微落后 | 比计划高 0.5 kg 以内 |
| 落后计划 | 比计划高 0.5 kg 以上 |
| 已达成目标 | 趋势体重已不高于目标体重 |

单次称重比前一天重了不用紧张，看趋势体重和状态标签即可。

### 4. 看懂图表

- **体重轨迹**
  - 紫色虚线：计划曲线，前快后慢；阴影是 ±0.5 kg 容差带
  - 灰点：每天的称重
  - 蓝色实线：趋势体重
  - 橙色点线：按当前建议摄入推算的预测
  - 紫色图钉：目标；竖线：今天
- **每日热量**：红线是预计消耗，绿线是建议摄入（每周校准时会变），柱子是热量缺口。
- 拖动图下方的滑块，或在图上双指缩放、滚轮缩放，可以调整时间范围。点击或悬停在某一天，可以看到当天的全部数据。两张图联动。

### 5. 身体成分与每日报告

- **概览 → 行动方案**：从今天的趋势体重出发，给出三种方案：保持目标日期需要吃多少、额外运动多少（折算成快走分钟和步数）；只按安全下限吃何时达成；按每周 ≤ 1% 的安全速度何时达成。同时对比实际速度和模型预期，估算每天有多少缺口没有落实。
- **身体成分**：BMI（中国标准分级）、体脂率（Gallagher 分级）、肌肉率、水分率、骨量、按去脂体重算的基础代谢，以及 BMI、体脂率趋势和目标体重时的对比。
  - 有阻抗（体重秤光脚测量）时用小米体脂秤开源社区的 BIA 公式，否则用 Deurenberg 公式按 BMI 估算。
  - 和米家 App 的新算法可能相差 2–3 个百分点，只适合看趋势。
- **每日报告**：选某一天，看当天体重、与前一次的变化、趋势和计划对比、当天热量、前后两周走势和当天的身体指标。

### 6. 健身房训练

「训练」标签页给出当天去健身房的安排，做成可以逐项打勾的清单，打勾自动保存：

- **热身 → 力量 → 跑步机 → 拉伸**，顶部的时间条显示每部分多少分钟。默认工作日 60 分钟、周末 80 分钟，可以切换 45/60/75/90。
- **力量训练**按 A 下肢+核心 → B 上肢推 → C 上肢拉 轮换，练过（打过勾）才往后排，每天去或隔天去都适用；连续练满 3 天安排一次恢复训练。可以手动换成别的。
- 每个动作有器械示意图、组数和每组次数（圆圈，做完一组点一下）、组间休息、动作要点和器械被占用时的替代动作。重量用 ± 记录，上次全部完成时下次建议加 2.5 kg。
- **跑步机**用坡度图展示每一段的坡度和速度，并给出心率区间。BMI ≥ 30 时只安排爬坡走、不安排跑步。
- 下方「最近两周」显示每天练了什么、完成了多少；点进某一天可以补打勾。未来的日期只能预览。

### 7. 每周校准

从计划开始日起，每 7 天用当时的趋势体重和剩余天数重新计算一次建议摄入，一周之内保持不变：

- 落后了，建议摄入会下调；超前了，会适当放宽。
- 建议摄入不会低于安全下限（男 1500 / 女 1200 kcal）。如果按期达成需要的摄入低于下限，就按下限给出建议，同时提示预计的达成日期。
- 历次校准结果列在页面最下方的「每周校准」表里。

### 8. 提示信息

| 提示 | 怎么办 |
|---|---|
| 计划减重速度偏快 / 过快 | 每周减重超过体重的 1%（超过 1.5% 标红），按提示把目标日期延后 |
| 摄入低于安全下限 | 按提示每天增加运动，或延后目标日期 |
| 目标 BMI 低于 18.5 | 目标体重偏瘦，建议调高 |
| 按当前进度需要的摄入低于下限 | 进度落后太多，已按下限给建议；可以考虑延后目标日期 |
| 可能进入平台期 | 近 14 天趋势体重几乎没降：检查实际摄入有没有超出建议、增加日常活动，或安排 1–2 周按维持热量吃，再继续 |
| 已经 N 天没有称重 | 距上次称重已有 3 天或更久，恢复每天称重 |
| 已达到目标体重 | 建议摄入自动切换为维持热量 |
| 目标日已过 | 在「计划设置」里制定新计划 |

### 9. 修改计划

- 在「计划设置」里改完保存即可，整条计划曲线会按新设置重新计算，**旧计划不会保留**。
- 想从今天重新开始一个新计划，把「计划开始日期」改成今天。「起始体重」留空时，会自动取今天的趋势体重。

## 算法说明

| 环节 | 做法 |
|---|---|
| 趋势体重 | 每天取最早一次称重；对最近 21 天的数据按 10 天半衰期加权做线性拟合，取当天的拟合值。能滤掉日常的水分波动，体重持续下降时也不会像移动平均那样滞后 |
| 每日消耗 | Mifflin-St Jeor 基础代谢 × 活动系数，加上设置里的每日额外运动 |
| 计划曲线 | 约 7700 kcal 对应 1 kg。体重下降后消耗也下降，所以固定摄入时体重沿指数曲线下降（前快后慢）。反解出"目标日正好到达目标体重"的每日摄入 |
| 安全检查 | 每周减重不超过体重的 1%（超过 1.5% 标红）；每日摄入不低于男 1500 / 女 1200 kcal；目标 BMI 不低于 18.5。不满足时给出最早的安全日期，或需要补充的运动量 |
| 每周校准 | 每 7 天用当时的趋势体重和剩余天数重新求解建议摄入。落后了就自动收紧，但不低于安全下限 |
| 状态判断 | 趋势体重与计划曲线比较：不高于计划为"按计划"，高出 0.5 kg 以内为"略微落后"，超过 0.5 kg 为"落后" |
| 平台期 | 计划进行 14 天以上、近 14 天趋势体重每周下降不到 0.1 kg 时提醒 |
| 营养素 | 蛋白质按目标体重 1.6 g/kg，脂肪占 25% 热量，其余为碳水 |

## 接口

| 方法 | 路径 | 说明 |
|---|---|---|
| POST | `/api/login` | 网页登录，`{"password": "..."}`，成功后写入 Cookie；`/api/logout` 退出 |
| GET | `/api/session` | 当前身份：`web`、API 令牌名称，或未启用验证时为 `null` |
| GET | `/api/training?day=` | 某一天（默认今天）的训练清单 |
| PUT | `/api/training/{day}` | 保存打勾、重量、手动选择的训练和可用时间，`{"checked": [...], "weights": {"leg_press": 60}, "template": null, "budget": null}` |
| GET | `/api/dashboard` | 今日卡片、图表数据、警告、每周校准记录 |
| GET / PUT | `/api/profile` | 计划设置 |
| GET | `/api/weighins?limit=60` | 最近的称重记录 |
| POST | `/api/weighins` | 新增称重 |
| PATCH | `/api/weighins/{id}` | 修改体重或时间，`{"weight_kg": 81.2, "measured_at": "2026-10-17T07:30"}` |
| DELETE | `/api/weighins/{id}` | 删除称重 |
| POST | `/api/weighins/import` | 批量导入，`{"csv": "2026-09-01,86.2\n..."}` |

第 2 阶段 ESP32 上报示例：

```bash
curl -X POST http://mac-mini.local:8765/api/weighins \
  -H 'Content-Type: application/json' \
  -H 'X-API-Key: <令牌>' \
  -d '{"weight_kg": 81.3, "impedance_low": 512.3, "impedance_high": 470.1, "heart_rate": 68, "source": "esp32"}'
```

- 不传 `measured_at` 时按服务器当前时间记录。
- 来源不是 `manual` / `import` 时，同一来源 2 分钟内的多次上报会合并为一条（S400 会先后发出体重包和阻抗包）。

## ESP32 自动上报

配置在 `esp32/` 目录：

1. 复制 `esp32/secrets.example.yaml` 为 `esp32/secrets.yaml`，填写 WiFi（必须是 2.4 GHz）、秤的 bindkey 和蓝牙 MAC 地址、上报地址（公网需 HTTPS，固件会校验证书），以及 `api_token`（和服务器 `.env` 里 `WP_API_TOKENS` 的 esp32 令牌一致）。
2. USB 连接 ESP32，编译烧录并查看日志：

   ```bash
   cd esp32
   uvx --from esphome==2026.10.0b4 esphome run weight-scale.yaml
   ```

   之后改配置可以无线升级：`esphome run weight-scale.yaml --device weight-scale.local`。

3. 光脚上秤，等米家显示完体脂等数据再下来。约 10 秒后页面上会出现一条来源为 `esp32` 的记录。

注意：

- 称重时手机上的米家 App 如果正连着秤，秤可能不发广播，这一次 ESP32 收不到。
- 上报失败（服务器没开）时，这一次数据会丢弃，不会重试。
- 改了 esp32 令牌后，要同步改 `secrets.yaml` 并重新烧录，否则上报会返回 401（日志里显示“上报完成，HTTP 401”）。
