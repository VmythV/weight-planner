减重计划 · 系统架构

体重秤的蓝牙广播由 ESP32 解密后，通过 WiFi 上报到 Mac mini 上的 FastAPI 服务；服务把数据存进 SQLite，计算计划和趋势，再由浏览器页面展示。

一次称重的数据流

  1. 光脚上秤。秤在约 1 秒内先后广播两个加密包：体重 + 心率 + 50 kHz 阻抗，然后是 250 kHz 阻抗。每个包重复广播约 7–8 次。
  2. ESP32 持续扫描（窗口 300/320 ms），用 bindkey 解密。第二个包体重字段是 0x7FF，组件误读成 204.7 kg，配置里把它过滤掉，并把阻抗改记为高频阻抗。
  3. 最后一个包到达后安静 10 秒，ESP32 把这一轮数据合并成一次 POST /api/weighins（请求头带 X-API-Key 令牌），缺的字段直接省略。
  4. 服务端按服务器时间记录；同一自动来源 2 分钟内的多次上报会再合并一次，作为兜底。
  5. 页面每 60 秒刷新，/api/dashboard 用每天最早一次称重重新计算趋势体重、计划偏差和当天的建议摄入。

模块

采集层

  • esp32/weight-scale.yaml：ESPHome 配置
  • esp32/secrets.yaml：WiFi、bindkey、上报地址（不进 git）
  • 失败时只记日志，不重试；Mac mini 关机时那次称重会丢失

服务层

  • app/main.py：接口与校验（Pydantic）
  • app/planner.py：纯函数算法，无数据库依赖，单独可测
  • app/db.py：SQLite 读写与自动来源合并
  • tests/：pytest，覆盖算法与接口

数据与部署

  • 开发：uv run uvicorn ... --reload
  • 常驻：deploy/install-launchd.sh（登录后自启、崩溃自启）
  • 迁移：拷贝 data/weight.db + 改 ESP32 的 report_url

接口

接口用途
POST /api/login · /api/logout网页密码登录 / 退出（签名 Cookie，不需要令牌）
GET /api/session当前身份：web 或 API 令牌名称
GET /api/dashboard今日卡片、图表序列、警告、每周校准
GET / PUT /api/profile读取 / 保存计划设置
GET /api/weighins?limit=称重记录，时间倒序
POST /api/weighins新增称重；自动来源 2 分钟内合并
PATCH /api/weighins/{id}修改体重或时间
DELETE /api/weighins/{id}删除称重
POST /api/weighins/importCSV 批量导入
GET /api/body · /api/report?day=身体成分序列 / 某一天的报告
GET /api/training?day= · PUT /api/training/{day}健身房训练清单 / 保存打勾和重量

除登录接口和静态文件外，所有页面和接口都需要登录 Cookie，或请求头 Authorization: Bearer <令牌> / X-API-Key: <令牌>。密码和令牌配置在项目根目录的 .env。
